## Purpose and scope

Build a local, numerically trustworthy 3D tool for inspecting null geodesics in stationary Kerr spacetime. The pedagogical focus is comparing sub-extremal, extremal and super-extremal geometry, horizon crossings, frame dragging and supported signed-r continuations using actual computed trajectories.

The project name in earlier conversations included Kerr–Newman, but current physics is **uncharged Kerr, Q_bh = 0**. Keep the geometry interface extensible; charge physics is future work and must not be silently enabled.

Compare the same local launch definition in different stationary geometries. A future spin slider must recompute independent stationary solutions; it does not simulate a black hole evolving in time. Do not explain horizon disappearance as light being mechanically flung outward by frame dragging or force ray outcomes for a dramatic visualization.

This is a geometry inspection tool. Accretion disks, jets, background stars/lensing, realistic shadows, bloom, fake capture/escape animations, decorative frame-dragging grids, light/escape-cone overlays, and Doppler/redshift visual effects are outside the current scope.

## Physics architecture and conventions

Use geometric units **G = c = M = 1**, spin **a = a***, and the **+z** spin axis. The horizon polynomial is `Delta = r² - 2r + a²`; its roots are `r_± = 1 ± sqrt(1-a²)` when real. At exact extremality the roots coincide at r=1, with no artificial duplicate inner-horizon event. For |a|>1 there are no real horizon roots. In the Schwarzschild limit, r=0 is the point singularity, not a regular inner horizon.

The primary coordinates are Cartesian Kerr–Schild, with ingoing/outgoing horizon-penetrating patches. Null geodesics use the Hamiltonian:

```text
H = 1/2 g^(mu nu) p_mu p_nu = 0
dx^mu/dlambda = g^(mu nu) p_nu
dp_mu/dlambda = -1/2 (partial_mu g^(alpha beta)) p_alpha p_beta
p_t = -E (held fixed by stationarity)
```

SciPy **DOP853**, adaptive integration and **float64** physics are the validated baseline. Metric, inverse metric and derivatives are analytic. Finite differences are independent validation tools, not the production RHS.

Launches use the Eulerian observer orthogonal to Kerr–Schild time slices and a deterministic orthonormal spatial triad (the symmetric inverse-square-root construction). A stored `RayDefinition` preserves position, coordinate time, normalized local direction, frame convention and local frequency (normally `omega_local=1`). Construct the null tangent in that frame, then lower its index with the metric. Eulerian launches require the existing frame/domain preconditions, including `g^tt<0`.

At every new spin, rebuild geometry, observer frame, initial covector, E, L_z and Carter constant. Never reuse another spin's momentum or conserved quantities.

### Signed-r and coordinate continuation

The r=0 disk is not entirely singular. Regular disk passages with positive Sigma can continue to the negative-r sheet; the singular ring (or Schwarzschild point) has a separate approach guard.

The v0.1D inclined a=0.7 ray turned inside the inner horizon and encountered an outgoing branch poorly represented by the ingoing chart. Divergent coordinate momenta and a tiny-step solver failure were not evidence of singularity contact. v0.1E added signed-sheet/hemisphere bookkeeping and ingoing/outgoing handoffs using the full coordinate Jacobian and canonical covector transformation; v0.1F extended branch selection for validated extremal and other cases.

Recorded states are **piecewise chart coordinates**. Consult per-sample chart, branch and region metadata and ordered transitions. Geometry owns coordinate transformations, including canonical ingoing Cartesian positions used for display. Rendering must not directly join incompatible chart coordinates.

## Termination and trust

Horizon crossings are recorded **nonterminal** events.

| Status | Interpretation |
| --- | --- |
| `ESCAPED` | Outward crossing of the finite configured escape boundary, including supported negative-sheet escape. |
| `SINGULARITY_APPROACH` | Finite Sigma threshold near the singularity; not exact ring/point contact. |
| `MAX_INTEGRATION_LIMIT` | Integration budget reached. |
| `CHART_BOUNDARY` | Required safe coordinate continuation unavailable. |
| `NUMERICAL_ERROR` | Solver or numerical evaluation failed. |
| `DIAGNOSTIC_FAILURE` | Null/conservation reliability guard failed; not a physical fate. |

Assess status together with `COMPLETE`, `PARTIAL` or `UNRELIABLE`. Only accepted finite escape/singularity-approach results are COMPLETE. Partial prefixes establish no terminal fate; unreliable results establish no physical fate.

Keep the fixed **1e-8** scaled-null, scaled-L_z and scaled-Carter guard, solver checks and chart/domain checks. This guard is an empirical rejection criterion, not a proven global error bound. E is fixed through p_t, so its drift is not an independent integration test. Check sensitive classifications with tighter tolerances.

Never extend an endpoint into the red singularity marker or smooth a trajectory to make its shape look plausible. Cancellation/supersession and compute `DONE` are separate from physical termination and per-ray reliability.

It has a free fly/orbit camera, translucent outer-horizon spheroid when present, point/ring singularity marker, axis, colored trajectories and a diagnostic panel. **Interactive launch, crosshair, live spin slider and scheduler-connected live controls are planned.**

## Architectural boundaries

Maintain the flow: geometry → Hamiltonian/initial conditions → integrator → solve API → batch/performance backend → scheduler → viewer/UI.

- `src/kerr_geodesics/` owns metric equations, derivatives, launch frames, chart transformations, integration, events, diagnostics and compute APIs.
- `src/kerr_viewer/` consumes immutable/read-only results. It must not copy Kerr equations, modify launches/trajectories or run solves in rendering callbacks.
- Scheduler and physics remain independent of Qt/OpenGL; physics-only tests must work without GUI dependencies.
- Keep float64 physics; float32 GPU buffers are a display implementation detail.
- Preserve the independent reference backend alongside acceleration. Windows process entry points must remain spawn-safe.
- Avoid introducing charge physics, CUDA/GPU solvers, solver replacements or broad rewrites as incidental viewer work.

## Known limitations

The model is exact stationary Kerr, not collapsing/perturbed black-hole evolution. Supported continuations are not a complete global atlas or Penrose-block assignment. Astrophysical inner-horizon mass inflation is not modeled.

Escape uses a finite boundary rather than future null infinity. Singularity approach uses a finite Sigma threshold. Near-ring or separatrix rays can be tolerance-sensitive and may fail diagnostics. Sign-change event bracketing can miss multiple roots within one step. Sampled minima are not global minima, and SciPy's public DOP853 interface does not provide a reliable rejected-step count.

Keep these limits visible. A coordinate continuation, a displayed curve and a COMPLETE finite-boundary classification have different evidential scopes.
